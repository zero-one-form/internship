# QA計画と性能予算

## 自動テスト
| 種類 | コマンド | 内容 | 合格基準 |
|---|---|---|---|
| ビルド | `python3 build.py` | src と assets を1ファイルに連結 | 16MB以下 |
| 構文 | `node --check dist/game_only.js` | ゲームコードの構文 | エラーなし |
| 回帰 | `node tests/test.js` | jsdom上で約200項目（戦闘・依頼・深淵50層・ボス・保存・オンラインのオフライン動作・ミニゲーム） | 最終行 `ERRORS: 0` |
| 画面 | `node tools/snap.js 出力先 390 844` と `… 844 390` | 実Chromeで主要画面を撮影 | JSエラー0、目視で重なり・はみ出しなし |
| 重複チェック | `node tools/lint_dupes.js` | モジュール間で同じ名前の関数を宣言していないか（後の宣言が前を黙って上書きするため） | エラーなし |
| バランス測定 | `node tools/sim.js 3` | AUTOと簡単な方針（スキル習得・装備・祭壇・強化・壁で後退）で3時間ぶんを約4分で早送り。5分ごとのLv・到達階・所持金・死亡数など | 下の目安 |

### バランスの目安（ボット・2026-10-20）
ボットは人より効率がよい。人はおよそ2倍の時間がかかる想定。
| 到達 | ボット | 人の目安 |
|---|---|---|
| B20 | 20分 | 40分 |
| B40（最初の壁） | 40分 | 1.5時間 |
| B50 | 80分 | 2.5〜3時間 |
| 深淵の主 | 3時間で未討伐 | やり込みの目標 |

残っている課題：ゴールドが3時間で約900万たまり、使い道が足りない。

### 性能（ヘッドレスChrome、GPUなし）
ゲームの処理は敵128体・仲間6匹で1フレーム0.3〜0.4ms。重さはほぼ描画で、仲間6匹でも描画の負担は変わらない（39ms→39.5ms、GPUなし環境のため実機より大幅に遅い数値）。

CI（.github/workflows/ci.yml）が push ごとにビルド・構文・容量・回帰を実行し、配布物を成果物として保存する。

## 性能予算（ミドルクラスのスマホ）
| 項目 | 予算 | 現状の対策 |
|---|---|---|
| フレーム時間 | 16.7ms（60fps）。22ms超が3秒続いたら解像度を下げる | `adaptResolution`（d_ui.js） |
| 描画解像度 | DPR 最大2、自動で0.25ずつ下げて最低1.25 | `dprCap` |
| 地面チャンク | 1フレームの生成は最大1枚、キャッシュは表示数+10枚 | `drawChunks` の先読みを上限内に |
| 粒子 | 300（軽量モード110） | `addPart` |
| 配布サイズ | 16MB（現在約10.2MB） | CIで検査 |

## 不具合の扱い
1. 再現手順と原因（ファイル:行）を特定する
2. 直す前に失敗するテストを書く
3. 直して、テストが通ることを確認する
4. 「たまに失敗」は乱数・実時間タイマー・一時停止の状態を疑う（HANDOFF §7）
