# ロードマップと工程

## 工程（このプロジェクトでの進め方）
AAAタイトルの開発工程を、少人数・1ファイル配信の規模に合わせて縮めたもの。

| 段階 | やること | 完了の基準 |
|---|---|---|
| 1. 企画・プリプロ | 柱・ループ・数値の設計（docs/GDD.md） | 柱に照らして機能の要否を決められる |
| 2. 監査（マイルストーン審査） | コード不具合・性能・UX・設計の4方向レビュー | 指摘が優先度つきで一覧になっている |
| 3. 実装 | 1回の作業で1テーマ（不具合／バランス／機能） | 回帰テスト合格、テストを追加済み |
| 4. QA | 自動テスト（jsdom）＋実ブラウザ撮影（縦・横） | `ERRORS: 0`、撮影でJSエラー0、表示崩れなし |
| 5. 公開 | dist を公開ページへ | 16MB以下、本番でオンライン機能を確認 |
| 6. 計測・調整 | 実プレイの数値で調整 | 次のマイルストーンの課題に反映 |

規則:
- **不具合を直したら、その不具合を再現するテストを必ず足す**（直す前に失敗し、直した後に通ることを確認）
- 「たまに落ちるテスト」は放置しない。原因を特定する（今回は本当の不具合が2件見つかった）
- 保存データの項目を足したら `load()` に検証を足す

## 未解決のリスク
| リスク | 影響 | 対応 |
|---|---|---|
| オンライン機能が本番未確認 | 共闘ボス・ランキングが動かない可能性 | 公開後に王冠ボタンの「通信：オンライン」を確認 |
| 主題歌の権利 | 配布できない可能性 | 依頼者に確認（HANDOFF §8） |
| 共闘ボスの「討伐済み」フラグは各自のドキュメントに書く | 権限を持つ参加者が不正に書けば週のボスを終わらせられる | 現状は組織内限定のため許容。外部公開時はサーバー側の検証が必要 |
| 古い保存データの胴防具が弱くなる（il55以上） | 既存プレイヤーの体感が下がる | 告知。必要なら既存胴防具に補正 |
